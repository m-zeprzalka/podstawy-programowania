## Pięć działań

```c title="kalkulator.c"
#include <stdio.h>

int main(void)
{
    int x = 7;
    int y = 2;
    printf("%d\n", x + y);    // 9
    printf("%d\n", x - y);    // 5
    printf("%d\n", x * y);    // 14
    printf("%d\n", x / y);    // 3, a nie 3.5!
    printf("%d\n", x % y);    // 1
}
```

Dwa ostatnie wyniki wymagają wyjaśnienia.

**Dzielenie liczb całkowitych daje liczbę całkowitą.** Gdy oba składniki są typu `int`, C odcina część ułamkową: 7 / 2 = 3, a 1 / 3 = 0. To **obcięcie**, a nie zaokrąglenie: 9 / 10 też daje 0.

**`%` to reszta z dzielenia.** 7 dzielone przez 2 to 3 i reszta 1. Reszta przydaje się częściej, niż się wydaje:

- `x % 2 == 0` sprawdza, czy liczba jest parzysta,
- `x % 10` daje ostatnią cyfrę liczby,
- `minuty % 60` zamienia minuty na „minuty po pełnej godzinie”.

## Jak dostać 3.5

Żeby dostać wynik z ułamkiem, przynajmniej jedna z liczb musi mieć typ z ułamkiem. Można to wymusić **rzutowaniem**, czyli typem w nawiasie przed wartością:

```c
printf("%f\n", (double) x / y);      // 3.500000
printf("%.2f\n", (double) x / y);    // 3.50
```

`(double) x` znaczy: „potraktuj x jako double”. Wtedy całe dzielenie odbywa się na liczbach z ułamkiem. `%.2f` w `printf` wypisuje dwie cyfry po kropce.

<Uwaga tytul="Rzutowanie w złym miejscu">
`(double) (x / y)` daje 3.000000. Nawias sprawia, że najpierw liczy się dzielenie całkowite (3), a dopiero gotowy wynik zamienia się na `double`. Rzutuj liczbę przed dzieleniem, a nie wynik.
</Uwaga>

## Ułamki nie są dokładne

W lekcji 0 widzieliśmy, że w JavaScripcie 0.1 + 0.2 nie daje dokładnie 0.3. W C jest tak samo, bo `double` to ten sam 64-bitowy format IEEE 754. Wystarczy poprosić `printf` o więcej cyfr:

```c
printf("%.20f\n", 0.1);           // 0.10000000000000000555
printf("%.20f\n", 1.0 / 3);       // 0.33333333333333331483
```

Typ `float` ma tylko 32 bity, więc błąd pojawia się dużo wcześniej:

```c
float f = 1.0f / 3;
printf("%.20f\n", f);             // 0.33333334326744079590
```

Dlatego domyślnie używaj `double`, a pieniądze licz w groszach jako liczby całkowite.

## Przepełnienie w praktyce

Podwajajmy liczbę w pętli:

```c title="podwajaj.c"
#include <stdio.h>

int main(void)
{
    int n = 1;
    for (int i = 0; i < 33; i++)
    {
        printf("2^%d = %d\n", i, n);
        n = n * 2;
    }
}
```

```txt title="Koniec wyniku"
2^29 = 536870912
2^30 = 1073741824
2^31 = -2147483648
2^32 = 0
```

Liczba 2³¹ nie mieści się w `int`, którego maksimum to 2 147 483 647. Wynik „przekręca się” na liczbę ujemną, a potem na zero, zupełnie jak licznik kilometrów z lekcji 0.

<Uwaga tytul="W C to coś gorszego niż przekręcenie">
Formalnie przepełnienie liczby ze znakiem (`int`) to w C **zachowanie niezdefiniowane**. Standard nie mówi, co ma się wtedy stać, więc kompilator ma prawo założyć, że to się nigdy nie zdarzy, i tak przerobić kod, że wynik będzie zupełnie inny.<Zrodlo n={8} /> Wynik powyżej to tylko to, co zwykle widać w praktyce. Przekręcanie jest gwarantowane jedynie dla typów bez znaku (`unsigned`).
</Uwaga>

Jak się bronić? Wybierać typ z zapasem. Ten sam program z `long long` i wstawką `%lld` doliczy bez problemu do 2⁶²:

```c
long long n = 1;
printf("2^%d = %lld\n", i, n);    // 2^31 = 2147483648, 2^32 = 4294967296
```

Granice typów są zapisane w pliku `limits.h`: `INT_MAX` to największy `int`, a `LLONG_MAX` największy `long long`.<Zrodlo n={9} />
